1. Project Overview ▼

Project Description

The SEAL Hackathon Platform is a unified, comprehensive event management system designed specifically for organizing, executing, and evaluating academic and professional hackathons. It facilitates end-to-end hackathon lifecycle management including user registration, team formation, track assignments, project submissions, judging workflows, and final prize distributions.

Objectives

  • Streamline hackathon registration and team creation processes.
  • Provide a robust evaluation system for judges with customizable criteria.
  • Ensure secure and seamless authentication using JWT and Google OAuth2.
  • Automate tracking of rounds, submissions, and leaderboards.

Architecture & Technologies

Backend: Java Spring Boot, Hibernate/JPA, RESTful APIs, JWT Authentication, Spring Security.

Frontend: React/Vue (running on Vite, ports 5173/5174).

Database: Microsoft SQL Server (`HackathonDB`).

Mail Server: SMTP (Gmail) for event notifications.

2. Test Strategy ▼

Scope

In-Scope: Functional testing of all API endpoints, UI/UX testing for frontend applications, Database integrity checks, Security testing for JWT and Role-Based Access Control (RBAC), Load testing on critical endpoints (e.g., submission, scoring).

Out-of-Scope: Third-party Google OAuth2 infrastructure testing, SMTP provider infrastructure.

Ensure 99% defect-free production deployment, validate all business rules regarding team formation and grading, and ensure zero PII exposure.

5. Test Scenarios ▼

Authentication & Authorization

  • TS_AUTH_01: Verify user registration with valid and invalid data.
  • TS_AUTH_02: Verify OTP generation, delivery, and expiration logic.
  • TS_AUTH_03: Verify Login functionality and JWT token generation.
  • TS_AUTH_04: Verify RBAC (Role-Based Access Control) for all endpoints.

Event & Track Management

  • TS_EVT_01: Verify Organizer can create, update, and delete events.
  • TS_EVT_02: Verify state transitions (Draft -> Registration -> Ongoing).
  • TS_TRK_01: Verify tracks can be assigned to events and mentors to tracks.

Team & Submission

  • TS_TEAM_01: Verify participant can create a team and invite members.
  • TS_SUB_01: Verify team leader can submit repository and demo URLs before deadline.
  • TS_SUB_02: Verify submissions are blocked after round deadline.

Scoring & Judging

  • TS_SCORE_01: Verify assigned judges can view submissions.
  • TS_SCORE_02: Verify scoring logic against criterion max score and weight.
  • TS_SCORE_03: Verify leaderboard generation based on finalized scores.

7. Test Data Strategy ▼

Data Categories Generated for Automation

  • Valid Data: Standard emails (user@fpt.edu.vn), strong passwords, valid URLs.
  • Invalid Data: Malformed emails, SQLi strings in input fields, XSS payloads in Team Descriptions.
  • Boundary Data: Team names with 255 chars, 0 chars. Scores matching exactly max_score.
  • Null Data: Missing required fields (e.g., empty token, null event_id).
  • Role-based Data: Seeded users for every role (Admin1, Org1, Judge1, Part1_FPT, Part2_NonFPT).

Note: A massive database seed script `qa_seed.sql` has been prepared to inject 1000 users, 50 events, and 500 teams for robust environment testing.

17. Database Testing ▼

Verified Constraints & Integrity on SQL Server (HackathonDB):

  • Foreign Keys: Verified ON DELETE CASCADE for `team_member` when `team` is deleted. Verified constraint preventing deletion of `hackathon_event` if submissions exist.
  • Unique Constraints: Verified `(event_id, user_id)` in `event_registration`. User cannot register twice.
  • Data Types: Verified `DECIMAL(5,2)` for final_score handles decimal truncations correctly.
  • Triggers/Procedures: Tested trigger logic for updating `updated_at` timestamps on row modifications.

28. Automation Recommendations ▼

Framework Selection

  • Frontend (UI/E2E): Playwright (TypeScript) - Recommended for handling React/Vite modern rendering, fast execution, and excellent cross-browser support.
  • Backend (API): RestAssured (Java) or Postman/Newman - Integrates seamlessly with existing Spring Boot ecosystem.
  • CI/CD Integration: GitHub Actions. Currently missing automated test triggers on PR creation.

ROI & Coverage Goals

Automate 100% of P1 API scenarios (Auth, Team Creation, Scoring). Target 70% UI regression coverage. Estimated time savings per release cycle: 24 man-hours.
